# Axis Roadmap (Post v4.0.0)

본 로드맵은 Axis v4.0.0 코어가 이미 완성되었다는 전제에서 시작한다.  
모든 단계는 선택 사항이며, 자동화는 최종 단계에서만 검토된다.

***

## Phase 0 — Baseline (완료)

현재 상태는 다음을 포함한다.

*   RAW → MET → OVW → RESULT 파이프라인
*   재시도 상태 표현 (rename-only)
*   Staging 수명 관리 (active / warm / purge-edge)
*   수동 purge 절차
*   읽기 전용 결과 소비 및 CSV Export
*   운영 Runbook
*   Control-Plane 경계 문서
*   변경 거버넌스 정책

이 상태 자체가 제품이며, 되돌릴 기준점이다.

***

## Phase 1 — RESULT 소비 확장 (Low Risk)

목표는 결과를 더 잘 읽을 수 있게 하는 것이다.  
구조 변경은 없고 자동화는 도입하지 않는다.

### 포함 가능

*   NDJSON Export 추가
*   CSV 컬럼 확장(설명 메타데이터 한정)
*   월/주 단위 정적 리포트 템플릿
*   결과 비교 스크립트 (읽기 전용)

### 금지

*   RESULT 재작성
*   RESULT 기반 판단 또는 추천
*   결과를 이용한 파이프라인 제어

이 단계는 Axis 코어를 건드리지 않고 활용도를 높이는 목적이다.

***

## Phase 2 — Control-Plane 가시성 (Read‑Only)

목표는 보여주되, 만지지 않는 것이다.  
구조 변경과 자동화는 없다.

### 포함 가능

*   CLI 기반 RESULT 목록 및 요약 조회
*   실행 이력의 읽기 전용 시각화
*   정적 또는 반정적 대시보드

### 금지

*   실행 버튼 제공
*   자동 트리거
*   상태 수정
*   정책 입력 인터페이스

Control-Plane은 노출 계층으로만 존재한다.

***

## Phase 3 — 반자동 운영 보조 (Human‑in‑the‑Loop)

목표는 사람의 판단을 방해하지 않는 보조 수단 제공이다.  
구조 변경은 없으며 자동화는 권고 수준으로만 허용된다.

### 조건부 허용

*   실행 추천 표시 (실행은 하지 않음)
*   이상 상태 알림 (조치 없음)
*   리포트 자동 생성 (배포는 수동)

### 여전히 금지

*   자동 실행
*   자동 삭제
*   자동 재시도

사람이 마지막 동작을 하지 않으면 아무 일도 일어나지 않아야 한다.

***

## Phase 4 — 자동화 도입 검토 (Very High Bar)

목표는 반드시 필요할 때만 부분 자동화를 검토하는 것이다.  
아래 전제 조건이 모두 충족되어야 한다.

*   Phase 1\~3 운영을 6개월 이상 지속
*   모든 자동화 실패 시나리오 문서화
*   자동화 중단 스위치 별도 존재
*   결과 되돌림(rollback) 절차 명확

### 검토 대상

*   스케줄러
*   TTL 기반 자동 삭제
*   재시도 정책 자동화

이 단계는 언제나 보류 가능하며, 실행하지 않는 선택도 항상 허용된다.

***

## 전 단계 공통 금지 사항

모든 Phase에서 끝까지 수행하지 않는 항목은 다음과 같다.

*   자동 판단
*   점수 또는 등급화
*   예측 기반 정책
*   결과를 제어 신호로 사용
*   파이프라인 내부 상태 직접 조작

***

## 버전 규칙 요약

*   소비자 확장: v4.x
*   가시성 추가: v4.x
*   구조 변경: v4.1 이상
*   자동화 도입: 별도 메이저 버전
