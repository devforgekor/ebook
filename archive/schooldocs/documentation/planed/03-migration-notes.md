# Migration Notes

이 문서는 목표 설계를 현재 구현에 이식할 때 참고하는 메모다.

## 문서 성격

- 현재 구현 문서가 아니다.
- 목표 설계를 바로 운영 문서에 반영하지 않는다.
- 구현 완료 후 검증된 항목만 실제 운영 문서로 옮긴다.

## 우선순위 높은 이식 대상

1. admins 권한 모델 정교화
- super/sub 구분
- allowedDocumentTypes 적용

2. records 스키마 확장
- documentType
- validUntil
- 상태 전이 이력
- 덮어쓰기 정책 반영

3. registry 연간 비교 로직
- 신규/재직/퇴직 판정
- 연도별 명단 업로드 기준 정립

4. 안전교육 3년 기수제
- 안전교육만 별도 cohort 또는 정책 적용
- 나머지는 1년 단위 유지

5. 사용자 조회 기준 정리
- 이름 + 생년월일 조회
- 휴대폰 번호는 알림용으로 사용
- 조회 API와 관리자 API의 경계 구분

## 현재 논의로 확정된 정책

- 중복 제출: 무조건 덮어쓰기
- 안전교육만 3년 기수제
- 나머지는 1년 단위
- 인원 기준 필드: 이름, 생년월일, 휴대폰 번호
- 사용자 조회 입력: 이름 + 생년월일
- 알림: 휴대폰 번호로 알림톡 발송
- 데이터 폐기: 기준 시점 + 6년
- 장애복구 상세: 추후 논의

## 현재 구현 대비 차이 메모

- 현재는 submit 단일 함수 구조다.
- records 컨테이너는 존재하지만 documentType 정책 구조는 아직 없다.
- admins 컨테이너는 인프라 정의가 있지만 권한 로직은 아직 구현되지 않았다.
- registry 컨테이너는 인프라 정의가 있지만 연도 비교 로직은 아직 구현되지 않았다.
- 관리자 인증, AI 파이프라인, 상태조회 확장 API는 아직 목표 단계다.

## 구현 시 주의점

- 목표 설계를 한 번에 모두 넣지 않는다.
- 현재 코드와 충돌하는 항목은 별도 브랜치/문서에서 먼저 검증한다.
- 실제 구현이 끝난 항목만 README 또는 운영 문서에 반영한다.

## 추천 작업 순서

1. 데이터 모델 확정
2. 권한 모델 확정
3. registry 비교 배치 설계
4. documentType 정책 테이블 도입
5. 실제 API/화면 흐름 확장

## 문서 관리 규칙

- 이 문서는 계획 문서다.
- 실제로 구현된 내용만 운영 문서에 반영한다.
- 큰 설계 변경이 생기면 이 문서를 먼저 갱신한 뒤 구현 여부를 판단한다.
