# Target Architecture

이 문서는 인증서 관리 시스템의 목표 아키텍처를 정리한 계획 문서다. 현재 구현과 완전히 일치하는 운영 문서가 아니라, 추후 구현/이식 기준으로 사용하는 설계 기준본이다.

## 목표

- 학교 구성원의 교육 이수 문서를 통합 관리한다.
- 문서 종류는 추후 수십 개까지 확장 가능하도록 설계한다.
- 관리자 권한은 전체관리자(super)와 부관리자(sub)로 구분한다.
- 부관리자는 허용된 문서 종류에만 접근할 수 있다.
- 인원 관리는 매년 명단 업로드를 기준으로 신규, 재직, 퇴직을 판정한다.

## 문서 주기 정책

- 안전교육: 3년 기수제
- 청렴교육: 1년 단위
- 의무교육: 1년 단위
- 그 외 문서: 기본은 1년 단위로 시작하고, 필요 시 별도 정책을 추가한다.

## 배포 방향

- 호스팅: Azure Container Apps
- 데이터 저장: Azure Cosmos DB
- 파일 저장: Azure Storage Blob
- 비밀 관리: Azure Key Vault
- 이미지 저장소: Azure Container Registry
- CI/CD: Azure Pipelines

## 인프라 목표 상태

- Azure Container Apps를 기본 런타임으로 사용한다.
- 공용 HTTPS 엔드포인트를 사용하되, 필요 시 학교 내부망 IP 제한을 적용한다.
- Key Vault와 Managed Identity를 기본 비밀 관리 방식으로 사용한다.
- ACR 이미지를 기준으로 앱을 배포한다.
- 비용 제약을 고려해 무료 할당량 안에서 운영 가능하도록 설계한다.

## 스케일링 목표

- 기본은 HTTP 스케일링
- 목표 상태에서는 필요 시 평일 업무시간 기준 Cron 스케일링을 추가한다.
- 공휴일과 야간에는 scale-to-zero를 허용한다.
- 콜드 스타트는 허용 가능한 운영 특성으로 간주한다.

## 애플리케이션 구조 원칙

- 인프라는 하나로 유지한다.
- Docker/배포 단위는 가급적 하나로 유지한다.
- 문서 종류는 타입 기반으로 확장한다.
- 비슷한 문서들은 같은 로직 패밀리를 공유한다.
- 공통 엔진과 타입별 정책을 분리한다.

## 문서 타입 확장 원칙

- 문서 종류별로 폴더는 분리할 수 있다.
- 하지만 로직 전체를 복제하지 않는다.
- 공통 처리:
  - 업로드
  - 저장
  - 권한 검증
  - 상태 전이
  - 로깅
- 타입별 처리:
  - 유효기간
  - 파싱 규칙
  - 필수 필드
  - 업로드 경로

## 관리자 권한 원칙

- super: 모든 문서 종류 관리 가능
- sub: 허용된 문서 종류만 관리 가능
- 권한 판단 기준은 문서 종류(documentType 또는 certificateType)다.

## API 목표 구조

- 사용자 API와 관리자 API를 구분한다.
- 사용자 API는 제출, 상태 확인, 결과 조회를 담당한다.
- 관리자 API는 승인, 반려, 명단 업로드, 관리자 관리, 기수 관리를 담당한다.
- 관리자 API는 Easy Auth 또는 동등한 인증 체계를 통해 보호한다.
- 익명 API와 관리자 API의 신뢰 경계는 코드에서 명확히 분리한다.

## 사용자 흐름

- 사용자는 이름과 생년월일로 자신의 제출 상태를 조회한다.
- 휴대폰 번호는 알림톡 발송에 사용한다.
- 비밀번호는 우선 도입하지 않는다.
- 추후 접속 제한(IP 제한 등)으로 보안을 강화한다.

## 운영 정책

- 중복 제출은 무조건 덮어쓰기
- 장애복구 상세 정책은 추후 논의
- 현재 문서는 목표 설계 기준으로 유지하고, 실제 운영 문서는 별도로 관리한다.

## 로깅과 모니터링 목표

- Audit 로그와 Error 로그의 목적을 분리한다.
- 장기 보존이 필요한 로그와 단기 디버그 로그를 분리한다.
- 향후 App Insights와 Log Analytics를 역할별로 나눠 사용할 수 있도록 설계한다.

## 보안 원칙

- 개인정보는 암호화 또는 해시 처리한다.
- 비밀값은 Key Vault를 통해 관리한다.
- 관리자 권한은 데이터 기반(admins)으로 판정한다.
- 사용자 조회는 최소 입력만 허용하되, 추후 추가 보안 절차를 붙일 수 있도록 열어 둔다.
